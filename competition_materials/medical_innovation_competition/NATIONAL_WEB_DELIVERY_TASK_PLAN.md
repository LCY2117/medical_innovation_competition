# 生命反射弧国赛网页端交付长任务计划

更新时间：2026-05-26

## 目标

把“生命反射弧”打磨成可用于第十二届全国大学生医学创新大赛国赛展示的网页端作品。当前定位为本科组、实验设计类、交叉学科、AI 创新设计。

## 验收口径

本轮交付必须支撑：

- 公网总控台展示。
- 一台电脑四端 `/mobile` 演示。
- 模拟急救协同流程闭环。
- 比赛证据材料导出。
- 低成本桌面模拟预实验。
- 5 分钟中文答辩叙事。
- 摘要、PPT、实验记录、专家反馈等材料链。
- 盲审安全和医学安全边界。

详细验收标准以 `docs/LONG_TASK_STATE.md` 顶部的 `Current Session Acceptance Standard - Medical Innovation National Web Delivery` 为准。

## 非目标

- 不接入 OPPO 健康 SDK。
- 不把 Android APK 作为本轮主展示依赖。
- 不申请新的第三方 SDK 或 API。
- 不伪造真实 AED 点位、专家签字、真人实验或临床数据。
- 不宣称临床疗效或抢救成功率提升。

## 工作流

1. 建立长任务状态、阻塞队列、Git 基线和子 agent 台账。
2. 审计 Web 总控台、`/mobile` 四端演示、证据包和比赛材料。
3. 实现国赛展示关键优化。
4. 补强证据包、预实验材料和答辩叙事支撑。
5. 运行构建/测试/浏览器验证。
6. 通过 Git/SSH/deploy 工作流部署公网。
7. 输出最终交付报告和后续团队事项。

## 优先级

- P0：总控台、四端演示、证据导出、比赛叙事、部署验证。
- P1：材料模板、截图/视频清单、预实验汇总辅助、Q&A 支撑。
- P2：视觉细节、附加统计、长期 App/SDK 扩展说明。

## 验证要求

- Web 相关修改至少运行 `npm run typecheck` 和 `npm run build`。
- 后端证据包或 API 修改需运行相关 Python 单元测试。
- 关键演示路径需用浏览器验证，但业务流验证放在实现阶段，不作为开工前预检。
- 部署后需验证公网入口、静态资源、API 健康和核心演示入口。

## 子 Agent 治理

允许使用子 agent。每个子 agent 必须登记 id、昵称、职责、读写权限、文件范围、预期输出、状态和关闭情况。尽量避免重叠写同一批文件。

## 真实外部事项

- 真实云南大学 AED 点位由团队后续人工标记。
- 专家反馈和签字由团队联系专家完成。
- PPT 最终风格和现场讲稿由团队确认。
