# 生命反射弧系统级模拟预实验方案

更新时间：2026-05-25

## 1. 方案定位

本方案用于时间有限、暂无法组织真人多角色预实验时，对“生命反射弧”进行系统级模拟预实验。

本方案不声称完成真实临床实验，也不声称完成多人真实急救协同训练。其定位是：

**桌面推演式系统模拟预实验。**

核心目的：

- 验证系统能否从事件触发、角色分派、任务同步、流程推进到证据包导出形成闭环。
- 验证 AI/规则分派、WebSocket 同步、mobile 多端页面、事件状态机和实验数据导出是否可用。
- 为 PPT、摘要和专家反馈提供初步工程可行性证据。

推荐对外表述：

本项目在国赛准备阶段完成了系统级模拟预实验。实验通过同一测试者在桌面环境中模拟患者端、核心施救端、AED 保障端和环境清障端，连续运行多轮急救协同流程，验证系统从事件触发、角色分派、多端任务同步、流程推进到预实验证据包导出的完整闭环。该结果用于证明技术路线和数据记录能力，不替代真人预实验、医学临床验证或急救效果评估。

## 2. 实验边界

### 2.1 可以证明什么

- 系统流程能跑通。
- 多端状态能同步。
- 角色任务能被分派并推进。
- AED/CPR/交接节点能被记录。
- 预实验证据包能导出。
- AI 或规则调度能生成可解释结果。
- 多轮运行可以产生可汇总的时间线数据。

### 2.2 不能证明什么

- 不能证明真实抢救成功率提升。
- 不能证明真人紧张状态下操作一定流畅。
- 不能证明系统可直接用于真实急救现场。
- 不能替代医学伦理审批、临床试验或急救培训认证。
- 不能把同一测试者多角色点击包装成真人多角色预实验。

## 3. 实验环境

### 3.1 系统环境

| 项目 | 内容 |
| --- | --- |
| Web 调度台 | https://lifereflex.mddcommunity.top/ |
| mobile 端 | https://lifereflex.mddcommunity.top/mobile |
| 后端服务 | 公网服务器部署的 LifeReflexArc API |
| 浏览器 | Edge / Chrome |
| 网络 | 宽带或稳定热点 |
| 终端数量 | 1 台电脑，4 个浏览器标签页模拟 4 个 mobile 角色 |

### 3.2 角色设置

| 模拟角色 | 页面 | 操作说明 |
| --- | --- | --- |
| 总控端 | Web 调度台 | 初始化场景、指定患者、观察状态、导出证据包 |
| 患者端 | mobile 标签页 1 | 触发 SOS 或被指定为患者 |
| 核心施救端 | mobile 标签页 2 | 响应任务、开始 CPR、推进 AED 相关步骤 |
| AED 保障端 | mobile 标签页 3 | 响应任务、取到 AED、送达 AED |
| 环境清障端 | mobile 标签页 4 | 响应任务、完成清障和救护接应 |

## 4. 实验设计

### 4.1 类型

单机多端、桌面推演、系统级模拟预实验。

### 4.2 轮次

建议至少 3 轮，最好 5 轮。

| 轮次 | 场景差异 | 目的 |
| --- | --- | --- |
| R001 | 默认演示场景 | 验证基础闭环 |
| R002 | 更换患者端 | 验证不同患者指定 |
| R003 | 更换 AED 点位或位置 | 验证 AED 因素进入流程 |
| R004 | 模拟 AI 不可用或规则兜底 | 验证 fallback |
| R005 | 快速连续点击或刷新页面 | 验证幂等和同步稳定性 |

### 4.3 观测指标

| 指标 | 定义 | 来源 |
| --- | --- | --- |
| T0 | 患者触发或被指定为患者 | 系统日志 |
| T1 | 角色分派完成 | 系统日志 |
| T2 | 核心施救端响应 | 系统日志 |
| T3 | CPR 开始 | 系统日志 |
| T4 | AED 取到 | 系统日志 |
| T5 | AED 送达 | 系统日志 |
| T6 | 救护接应或交接完成 | 系统日志 |
| E1 | 是否成功导出证据包 | 人工记录 |
| E2 | 是否出现同步异常 | 人工记录 |
| E3 | 是否出现重复日志或按钮误触 | 人工记录 |

### 4.4 成功标准

每轮满足以下条件即判定系统级模拟成功：

- 角色分派成功生成。
- 3 类救援角色均能看到对应任务。
- CPR、AED 取到、AED 送达、救护接应至少 4 个关键节点能进入时间线。
- 事件可归档或可进入完成态。
- 证据包可导出。
- 导出文件包含时间线、指标、匿名化数据或 review index。

## 5. 操作流程

### 5.1 准备阶段

1. 打开 Web 调度台。
2. 输入演示口令。
3. 点击初始化演示场景。
4. 使用总控台的一键开启 4 个 mobile 标签页功能；如果浏览器拦截弹窗，则手动复制 4 个 mobile 链接。
5. 确认每个 mobile 页面已进入同一个事件或可接入当前事件。
6. 打开屏幕录制工具，准备记录全流程。

### 5.2 单轮实验流程

1. 在总控台重置或初始化事件。
2. 指定 mobile 标签页 1 为患者端。
3. 观察总控台是否生成 AI/规则分派结果。
4. 切换到核心施救端，点击响应或进入任务。
5. 切换到 AED 保障端，点击响应、取到 AED、送达 AED。
6. 切换到环境清障端，点击响应、完成清障或救护接应。
7. 回到核心施救端，推进 CPR、AED 分析、除颤后恢复 CPR 等节点。
8. 回到总控台，检查现场时间线和角色状态。
9. 归档事件或导出预实验证据包。
10. 记录本轮问题和证据包文件名。

### 5.3 多轮实验流程

每轮结束后：

1. 下载证据包。
2. 记录 ZIP 文件名、生成时间、事件 ID。
3. 把证据包放入统一目录。
4. 填写 `SYSTEM_SIMULATION_RECORD_TABLE.md` 中对应轮次。
5. 如系统提供多轮汇总脚本，可对多个 ZIP 运行汇总分析。

## 6. 数据记录模板

建议使用本文件夹中的：

- `SYSTEM_SIMULATION_RECORD_TABLE.md`
- `PPT_SAFE_RESULT_TEXT.md`

最少需要记录：

- 轮次编号
- 事件 ID
- 是否成功分派
- 是否成功导出证据包
- T1-T6 是否完整
- 主要异常
- 证据包路径
- 截图或录屏路径

## 7. 数据分析方法

由于本实验为同一测试者桌面推演，不做统计显著性分析。

可以做：

- 每轮 T1-T6 是否完整。
- 每轮流程是否成功闭环。
- 每轮导出证据包是否完整。
- 各关键节点耗时的描述性统计。
- 异常类型统计，例如同步延迟、页面刷新、按钮重复点击。

推荐图表：

- 多轮流程闭环成功率表。
- T1-T6 节点完整性矩阵。
- 每轮关键耗时柱状图。
- 系统异常和修复记录表。

## 8. PPT 可用结论

安全结论：

在桌面推演式系统模拟预实验中，生命反射弧完成了从事件触发、角色分派、多端任务同步、AED/CPR 流程推进到证据包导出的闭环。多轮结果初步说明，系统具备支撑后续真人低风险场景预实验和专家复核的工程可行性。

必须带上的局限：

该实验由同一测试者模拟多角色操作，主要验证系统流程和数据记录能力，尚不能代表真实多人协同中的操作负荷、紧张情境可用性或临床效果。后续需要组织真人低风险场景预实验，并邀请急诊、院前急救或护理相关专家复核流程合理性。

## 9. 答辩口径

如果评委问：你们有没有真人实验？

回答：

目前完成的是系统级模拟预实验，重点验证技术路线、事件流程和数据导出闭环。由于国赛准备周期有限，我们没有把桌面模拟包装成真人预实验或临床数据。下一阶段已准备低风险真人预实验方案、参与者问卷和专家反馈表，将进一步验证真实多人场景下的可用性和医学流程合理性。

如果评委问：这个数据有什么价值？

回答：

它的价值在于证明系统已经不是静态原型，而是能够连续运行完整流程，并自动生成可复盘的数据证据。对于实验设计类项目，这可以支撑技术路线可行性和后续预实验扩展，不用于证明临床疗效。
