# 国赛网页端 5 分钟演示 Runbook

更新时间：2026-05-26

适用场景：第十二届全国大学生医学创新大赛国赛网页端展示，定位为本科组、实验设计类、交叉学科、AI 创新设计。本文用于现场路演和录屏演示，不作为临床说明书。

核心口径：本项目展示的是“急救协同训练与流程记录原型”，通过 Web 总控台、`/mobile` 四端协同和证据包导出，验证系统级模拟流程闭环。当前不宣称临床疗效，不宣称提升抢救成功率，不替代 120、AED 厂商设备说明或专业医护判断。

## 1. 演示前准备

### 1.1 设备与页面

建议使用一台笔记本电脑完成演示，浏览器准备 5 个标签页：

| 标签页 | 用途 | 建议命名 |
| --- | --- | --- |
| Web 总控台 | 展示事件、角色、调度解释、时间线和证据包入口 | 总控台 |
| `/mobile` 患者端 | 模拟事件触发或患者状态信息 | 患者端 |
| `/mobile` 核心施救端 | 模拟 CPR / AED 流程执行 | 施救端 |
| `/mobile` AED 保障端 | 模拟取 AED、送达和设备状态反馈 | AED 端 |
| `/mobile` 环境清障端 | 模拟引导、清场、接应 120 等任务 | 清障端 |

如果现场网络不稳定，应提前准备本地录屏或截图备份。录屏只能作为工程演示备份，讲解时仍需说明其为模拟场景。

### 1.2 数据与安全口径

- 使用模拟事件、模拟角色和脱敏数据，不使用真实患者身份信息。
- AED 点位如未完成真实人工核验，只能表述为“样例点位”或“待人工核验点位”。
- 预实验结果只能表述为“系统级模拟预实验”或“桌面推演式预实验”。
- 不展示真实医疗处置建议的自动决策结论，所有 CPR / AED 内容仅作为流程训练提示。
- PPT、网页和口播中避免出现“临床验证”“疗效显著”“抢救成功率提升”等结论性表述。

## 3. 逐段口播脚本

### 0:00-0:35 开场：问题与作品定位

各位老师好，我们的作品是“生命反射弧”，定位为公共急救场景下的 AI 辅助协同训练与流程记录系统。

在校园、体育场馆和公共空间中，突发心脏骤停事件往往不是缺少热心人，而是多人在最初几分钟里不知道谁报警、谁按压、谁去取 AED、谁维持现场秩序。我们希望用一个网页端原型，把这些角色任务快速组织起来，并把关键时间节点记录下来，供训练复盘和后续实验设计使用。

需要先说明的是，本项目当前是医学创新设计和系统模拟预实验，不宣称临床疗效，不替代 120、专业医护或 AED 设备说明。

### 0:35-1:10 总控台：AI 创新设计

现在看到的是 Web 总控台。总控台负责汇总事件状态、角色分派、任务进度和证据导出。

我们的 AI 创新点不在于让 AI 直接做医疗诊断，而是把突发事件中的人员、位置、任务优先级和急救流程拆成可解释的协同任务。例如系统可以辅助生成核心施救、AED 保障、环境清障等角色建议，并展示为什么这样分派。这样既保留了人类确认，也让比赛评审能够看到调度逻辑和证据链。

### 1:10-2:45 四端 `/mobile`：协同流程演示

接下来演示同一台电脑上的四个 `/mobile` 端，分别模拟四类参与者。

第一步，患者端触发模拟事件。这里使用的是预实验数据，表示某个公共空间出现需要急救协同的紧急场景。

第二步，核心施救端接到任务。页面引导志愿者完成到场确认、呼叫帮助、开始 CPR 流程和等待 AED 等关键节点。这里的提示用于训练和流程记录，不作为真实医疗诊断。

第三步，AED 保障端接到取 AED 任务。系统要求记录出发、到达 AED 点、返回现场和交付设备的时间节点。这样后续可以复盘 AED 获取是否成为瓶颈。

第四步，环境清障端负责维护现场秩序、接应 120、引导 AED 保障人员返回，并减少围观干扰。这个角色在真实场景中容易被忽视，但对协同效率很关键。

四端操作过程中，总控台会同步角色状态和时间线，形成一个可复盘的急救协同闭环。

### 2:45-3:30 总控台：实时状态与异常复盘

回到总控台，可以看到事件从触发到分派、执行、AED 保障和结束归档的过程。

这里我们重点展示三类信息：第一是角色是否已经接单并开始执行；第二是 T1 到 T6 等关键节点是否完整；第三是系统是否记录了调度解释、异常等待或角色缺口。

对实验设计类项目来说，这些记录比单纯展示页面更重要。它们说明系统不仅能演示交互，还能为后续多人低风险场景预实验、专家复核和论文式实验记录提供基础数据。

### 3:30-4:15 证据包导出：形成比赛材料链

现在点击证据包导出。证据包用于把一次模拟演示沉淀为结构化材料，包括事件摘要、时间线、角色任务、操作记录、调度解释和预实验记录字段。

这个设计服务于两个目标：一是让评委看到我们的工程闭环；二是让团队后续做低风险真人预实验时，能够按同一套字段收集数据，而不是演示完就没有可追溯材料。

如果现场导出失败，备用说法是：当前展示导出入口和字段结构，赛前会使用录屏和截图备份；正式材料中不会伪造专家签字、真实病例或临床数据。

### 4:15-4:45 预实验叙事：系统级模拟实验

国赛准备阶段，我们采用系统级模拟预实验。测试者在同一电脑环境下分别模拟患者端、核心施救端、AED 保障端和环境清障端，连续运行多轮协同流程。

这个预实验主要验证三件事：多端任务能否同步，关键时间节点能否记录，证据包能否导出。它初步证明了系统工程可行性和数据记录能力。下一阶段需要补充真人低风险场景预实验、问卷量表和医学专家反馈。

### 4:45-5:00 收束：边界与价值

最后再次强调，“生命反射弧”当前是急救协同训练和实验设计原型，不宣称临床疗效。它的价值是把突发急救前几分钟的多人协作变成可组织、可解释、可记录、可复盘的流程，为后续医学专家指导下的低风险场景预实验和真实场景研究打基础。

## 4. 现场操作清单

### 4.1 演示顺序

- 打开总控台，确认事件列表为空或使用已准备的演示事件。
- 打开四个 `/mobile` 标签页，分别切到患者端、核心施救端、AED 保障端、环境清障端。
- 患者端触发模拟事件。
- 总控台确认事件出现，检查角色分派和调度解释。
- 核心施救端确认接单并推进 CPR / AED 流程节点。
- AED 保障端推进取 AED、到达、返回、交付节点。
- 环境清障端推进清场、接应、引导节点。
- 总控台展示时间线和角色状态。
- 导出证据包或展示证据包生成入口。
- 切回 PPT 或总控台完成安全边界说明。

### 4.2 失败兜底话术

| 现场问题 | 兜底处理 | 口播建议 |
| --- | --- | --- |
| 网络或部署入口打不开 | 使用本地录屏或截图 | “当前使用赛前录屏备份说明流程，正式系统已按同一页面路径准备。” |
| 四端同步延迟 | 停在总控台解释设计 | “这里展示的是任务状态同步机制，延迟不影响本轮实验设计口径。” |
| 证据包导出失败 | 展示证据包字段模板 | “证据包字段已固定，导出失败会记录为工程问题，不把未生成材料伪造成结果。” |
| AED 点位缺少真实核验 | 明确为样例点位 | “真实点位需要团队后续人工核验，本页仅演示数据结构。” |
| 评委追问临床效果 | 回到边界 | “目前只完成系统级模拟预实验，不能推断临床疗效或抢救成功率。” |

## 6. 不可越界表述

| 不建议说 | 建议替换 |
| --- | --- |
| 系统提升了抢救成功率 | 系统用于验证急救协同流程闭环和记录能力 |
| AI 判断最优急救方案 | AI/规则辅助生成可解释的角色分派和任务建议 |
| 已完成临床验证 | 已完成系统级模拟预实验，后续需专家复核和真人低风险场景预实验 |
| AED 点位真实可用 | AED 点位需人工核验，当前可展示样例点位或已核验点位 |
