# 生命反射弧低成本预实验方案

## 1. 方案定位

本方案用于第十二届全国大学生医学创新大赛暨“一带一路”国际竞赛“交叉学科 / AI 创新设计”方向的作品验证材料准备。预实验不验证真实临床疗效，不替代急救培训或院前急救流程；其目的在于用低成本、可复现、可记录的模拟场景，验证“生命反射弧”在心脏骤停早期识别、多人协同分派、AED 取送、CPR 流程提示、事件数据留痕方面的工程可行性和医学应用相关性。

## 2. 医学应用场景

场景：校园、社区、医院门诊大厅、体育馆等公共场所出现疑似心脏骤停人员。

现实问题：

- 第一目击者可能紧张、不会分工，导致 CPR、AED、拨打急救电话等关键动作串行发生。
- 附近人员的专业能力、体力、位置、健康风险不同，人工口头协调效率低。
- AED 点位信息分散，取送路径和责任人不清楚。
- 事后难以获得完整时间线，无法评估流程瓶颈。

系统假设：

- 系统通过移动端和云端调度台，把“患者端、核心施救者、AED 取送者、环境清障/接应者”拆成并行任务。
- AI/规则调度根据人员画像、位置、AED 距离和风险提示进行角色推荐。
- 事件全程生成时间线、调度理由和导出数据，用于预实验分析和专家反馈。

## 3. 实验目标

主要目标：

- 验证系统能在模拟心脏骤停场景中完成从触发、分派、响应、CPR、AED 送达、救护接管到数据导出的完整闭环。

次要目标：

- 比较无系统协同与使用系统协同时，各关键动作的完成时间和分工明确度差异。
- 收集参与者对界面可理解性、任务指令清晰度、紧张情境可用性的主观评分。
- 形成可供医学专家审阅的事件记录、流程截图和改进意见材料。

## 4. 实验设计

类型：单中心、低风险、模拟场景、前后对照或组间对照预实验。

建议样本：

- 参与者 8-16 人。
- 每轮 4 人：患者模拟者 1 人、核心施救 1 人、AED 取送 1 人、环境清障/接应 1 人。
- 每组至少完成 2 轮：一轮无系统或口头分工，一轮使用生命反射弧系统。

场地：

- 走廊、教室、实验室、训练室或空旷区域。
- 预先标记患者点位、AED 模拟点位、救护车接应点。

材料：

- 生命反射弧 Web 调度台。
- 安装测试版 Android App 的手机 3-4 台。
- CPR 模拟人或替代道具；如无模拟人，使用标记垫，仅记录流程动作，不做真实按压。
- AED 模拟机或纸质/空盒模拟 AED。
- 计时器、观察记录表、参与者问卷。

伦理与安全：

- 不纳入真实患者，不采集敏感健康数据。
- 不进行真实电击，不在真人身上进行胸外按压。
- 参与者知情同意，可随时退出。
- 实验记录匿名化，盲审材料不得出现学校、学生、指导教师、照片等身份信息。

## 5. 流程

### 5.1 准备阶段

1. 部署云端网站，确认 Web、API、WebSocket 可用。
2. 安装 Android App，确认能连接 `https://lifereflex.mddcommunity.top/`。
3. 在系统中初始化演示场景或录入真实模拟点位。
4. 设定 AED 点位，例如“二楼服务台 AED”“校门值班室 AED”。
5. 给每位参与者分配匿名编号，例如 P01、R01、R02、R03。
6. 讲解实验安全边界：只模拟流程，不进行真实医疗操作。

### 5.2 基线轮：无系统协同

1. 观察员宣布“出现疑似心脏骤停”。
2. 参与者自行口头分工，完成呼救、CPR 模拟、取 AED、接应救护车等动作。
3. 观察员记录关键时间点和分工混乱情况。
4. 结束后参与者填写简短问卷。

### 5.3 系统轮：使用生命反射弧

1. Web 调度台点击“初始化医创赛演示场景”。
2. 选择患者端，触发心脏骤停模拟。
3. 系统自动给核心施救、AED 保障、环境清障角色下发任务。
4. 各终端按任务操作，依次记录加入、CPR 开始、AED 取到、AED 送达、AED 分析、救护接管。
5. Web 调度台下载“预实验证据包”ZIP，并记录包内 `manifest.json` 的生成时间与文件校验信息。
6. 观察员打开包内 `observer_record_form.csv`，补充记录无法由系统自动采集的行为、评分和开放反馈。
7. 如有专家现场参与，可让专家对照包内 `expert_review_checklist.md` 逐项复核。

## 6. 指标

### 6.1 时间指标

| 指标 | 定义 | 采集方式 |
| --- | --- | --- |
| T1 触发到分派完成 | 患者触发至三类角色分配完成 | 系统日志 |
| T2 触发到核心施救响应 | 患者触发至核心施救者点击加入 | 系统日志 |
| T3 触发到 CPR 开始 | 患者触发至 CPR 模拟开始 | 系统日志 + 观察记录 |
| T4 触发到 AED 取到 | 患者触发至 AED 保障者取到 AED | 系统日志 |
| T5 触发到 AED 送达 | 患者触发至 AED 到达患者点位 | 系统日志 + 观察记录 |
| T6 触发到救护接管 | 患者触发至环境清障者完成接应/交接 | 系统日志 |

### 6.2 质量指标

| 指标 | 评分方式 |
| --- | --- |
| 分工明确度 | 1-5 分，越高越明确 |
| 任务指令可理解性 | 1-5 分，越高越清晰 |
| 紧张情境可操作性 | 1-5 分，越高越容易操作 |
| 调度合理性 | 1-5 分，由参与者或专家评估 |
| AED 点位提示有效性 | 1-5 分 |
| 数据记录完整性 | 完整 / 部分缺失 / 缺失 |

### 6.3 AI 相关指标

| 指标 | 定义 |
| --- | --- |
| 角色推荐命中率 | 专家认为系统推荐角色合理的比例 |
| 调度解释完整性 | 是否包含人员能力、距离、AED、风险提示 |
| 规则兜底可用性 | AI Key 不可用时是否仍可完成分派 |
| 位置/AED 因素参与度 | 分派理由中是否体现位置和 AED 距离 |

## 8. 数据处理

建议输出：

- 每轮关键时间点折线图或条形图。
- 使用系统前后 T1-T6 的均值、中位数和范围。
- 参与者问卷均值和典型反馈。
- 系统导出的预实验证据包摘要：优先使用 `experiment_anonymized.json`、`clients_anonymized.csv`、`timeline.csv`、`metrics.csv`、`expert_summary.md`、`expert_review_checklist.md`、`observer_record_form.csv` 和 `pre_experiment_round_summary.csv`。
- 调度解释案例：展示为什么某人被分配为核心施救、AED 保障、环境清障。

统计原则：

- 小样本预实验以描述性统计为主，不做夸大显著性结论。
- 可以写“初步提示流程可行”“参与者主观评分较高”“发现若干交互改进点”。
- 不写“提高抢救成功率”“改善预后”等未验证临床结论。

## 9. 专家反馈准备材料

给专家看的材料包：

- 系统访问地址和测试账号。
- 3-5 分钟演示视频或现场演示脚本。
- 预实验流程图。
- 预实验证据包 ZIP 样例，含原始 JSON、匿名化 JSON/CSV、结构化时间线、指标表、调度依据、专家摘要、专家复核清单、观察员记录表、单轮汇总表和 `manifest.json` 校验清单。
- 对外展示和专家审阅优先使用匿名化文件，避免暴露真实账号、手机号、设备编号或个人身份信息。
- 调度解释截图。
- 专家反馈表。

建议截图清单：

| 截图编号 | 内容 | 用途 |
| --- | --- | --- |
| S01 | Web 调度台首页与演示口令状态 | 证明系统具备云端总控与公网演示保护 |
| S02 | 一键医创赛演示场景：4 个终端 + AED 点位 | 证明场景、角色和点位可初始化 |
| S03 | 患者 SOS / 心脏骤停触发状态 | 展示急救协同启动点 |
| S04 | 核心施救 / AED 保障 / 环境清障分派结果与评分理由 | 展示 AI/规则可解释调度 |
| S05 | AED 点位与 AED 保障者距离/取用说明 | 展示位置和 AED 因素进入流程 |
| S06 | 移动 Web 或 Android 任务页：我的任务、下一动作、现场时间线 | 展示低门槛移动端执行能力 |
| S07 | CPR/AED 分析/除颤/恢复 CPR 状态 | 展示急救流程提示闭环 |
| S08 | 证据包 ZIP 文件列表、`manifest.json`、`expert_summary.md` | 展示预实验数据可归档、可匿名化、可校验 |

3-5 分钟演示脚本：

1. 30 秒：说明医学场景。公共场所疑似心脏骤停，第一目击者、AED 取送者和清障接应者需要并行协同。
2. 40 秒：打开 Web 调度台，输入演示口令，初始化医创赛演示场景，展示 4 个终端画像和 2 个 AED 点位。
3. 40 秒：患者端触发 SOS，说明系统进入智能分派，结合人员画像、位置、AED 距离和健康风险生成核心施救、AED 保障、环境清障三类任务。
4. 60 秒：展示移动 Web 或 Android 端执行任务。PRIME 开始 CPR，RUNNER 取送 AED，GUIDE 接应救护车。
5. 40 秒：展示调度解释、现场时间线和 AED/CPR 下一动作提示，强调 AI 是辅助分派与解释，不替代 120 或专业医护。
6. 30 秒：完成交接归档，下载预实验证据包，展示匿名化数据、指标 CSV、专家摘要、专家复核清单、观察员记录表、单轮汇总表和 manifest 校验。

希望专家重点评价：

- 医学场景是否真实、有意义。
- 流程是否符合公众急救和院前急救基本原则。
- AI 分派逻辑是否有潜在风险。
- CPR/AED 提示是否需要更严格的医学表述。
- 作为医创赛作品，是否体现 AI 与医学问题的深度融合。

## 10. 可写入摘要/PPT的谨慎结论模板

本预实验基于模拟心脏骤停场景，验证了生命反射弧从事件触发、AI/规则分派、多人终端协同、AED 取送、CPR/AED 流程提示到实验数据导出的完整闭环。初步结果显示，系统能够形成可解释的角色分派和结构化时间线，为校园/社区急救演练提供低成本数字化工具。后续将扩大样本量，引入医学专家评审和更真实的 AED/CPR 培训环境，进一步优化安全提示、定位精度和调度策略。
