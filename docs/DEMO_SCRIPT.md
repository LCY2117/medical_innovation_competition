# 比赛现场演示脚本（3 分钟）

> 项目：生命反射弧（LifeReflexArc）—— 院前心脏骤停分布式应急协同系统
> 演示环境：Web 调度台 `https://www.yclsm.top/` + 手机端 `https://www.yclsm.top/mobile`

## 演示前准备（5 分钟）

1. **调度台**：浏览器打开 `https://www.yclsm.top/`，填入演示管理员口令（见 `docs/DEPLOYMENT.md`）
2. **手机端 × 4**：手机浏览器打开 `https://www.yclsm.top/mobile`，分别选患者端 / 核心施救 / AED 保障 / 环境清障
   - 若演示机不够，可用同一电脑开多个无痕窗口模拟
3. **确认状态**：调度台显示"在线 4/4"，患者端显示"实时同步中"

## 演示流程

### 开场（30 秒）
> "这是一个面向心脏骤停的院前应急协同系统。核心思路是'反射弧'：当有人倒下，系统像神经反射一样，
> 自动唤醒最近的急救力量、调度 AED、组织现场，把黄金 4 分钟的等待时间压缩到最短。"

### 第一步：触发 SOS（40 秒）
- **操作**：患者端点击"启动 SOS"→ 再次确认
- **讲解**：
  > "患者端一键触发求救，系统进入 5 秒确认倒计时——这是防误触设计。
  > 倒计时结束，系统自动完成角色分派。"

### 第二步：智能分派（20 秒）
- **操作**：展示调度台的分派结果（PRIME/RUNNER/GUIDE 三类角色）
- **讲解**：
  > "系统按专业能力、距离、体能、健康状态，自动从在线终端里选出：
  > 核心施救负责 CPR，AED 保障负责取送设备，环境清障负责通道和救护车接驳。"

### 第三步：协同执行（90 秒，可精简）
- **操作**：各端按提示点击按钮推进
  - 核心施救 → 确认开始 CPR（展示节拍器 110BPM 节拍 + 30:2 提示）
  - AED 保障 → 取到 AED → 送达
  - 核心施救 → 开始 AED 分析 → 完成除颤
  - 环境清障 → 救护车到达
- **讲解**：
  > "核心施救端有真实节拍器引导按压节奏，配合语音和震动提示。
  > AED 送达后自动进入分析、除颤流程。环境清障协调救护车到达，最后完成交接归档。"

### 第四步：证据包（20 秒）
- **操作**：调度台导出实验证据包
- **讲解**：
  > "整个流程自动生成实验证据包：响应耗时、CPR 启动时间、AED 送达时间、角色分配完整度、
  > 位置与健康数据覆盖率等指标，用于赛后复盘与研究分析。"

### 收尾（10 秒）
> "我们还能接入真实健康数据（Health Connect / OPPO 生态），让调度参考真实心率、血氧，
> 避免把高风险患者分配到高强度任务。"

## 话术要点

| 亮点 | 一句话 |
|---|---|
| **架构** | 患者端/响应端/调度台三端 + WebSocket 实时同步 |
| **智能分派** | AI 参考健康数据、距离、能力自动选人，防误分配 |
| **急救科学性** | 30:2 CPR 循环 + 节拍器 + AED 标准流程 |
| **防误触** | SOS 二次确认 + 倒计时 |
| **研究价值** | 全流程指标自动采集，导出证据包 |

## 兜底方案

- **服务器不可用**：演示前先 `curl https://www.yclsm.top/api/health` 确认
- **分派异常**：`dispatch/meta` 显示 `configured=false` 时走规则分派，仍能演示，话术可改为"当前演示用规则分派"
- **健康数据**：未授权时显示样例摘要，话术强调"接入真实数据后……"，避免承诺过度

## 恢复现场（每次演示后）

```bash
# 调度台或命令行重置事件，恢复 CREATED 状态
curl -X POST https://www.yclsm.top/api/incidents/current/reset -H "X-demo-Admin-Token: 你的口令"
```
